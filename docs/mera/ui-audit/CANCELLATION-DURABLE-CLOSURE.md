## Existing-contract correction

`GuestActivity.tsx` and `cancellationRecovery.ts` persist one bounded exact cancellation intent per branch before dispatch: original reservation, reason, request key and cookie-proven sessionRef. Storage readback is required; refusal/malformed state blocks replacement writes. Restore proves the current guest, hides private fields on mismatch and never POSTs automatically. Retry uses the existing endpoint's own-key replay before current status checks; no backend or cancellation-attempt API was added.

A cancelled activity row is not proof of which original request succeeded. The independent recovery panel remains until the explicit exact retry receives the validated original reservation result with `refundConfirmed:false`. Unknown and subsequent4xx cannot unlock a different reason/key. Late scope/guest reads cannot send an old cancellation. Explicit guest ending redacts matching-session journals across branches into opaque unresolved markers, leaves other guests' records untouched and fails closed if redaction cannot be saved. A marker is not cancellation/refund confirmation and has no private reason to resend.
