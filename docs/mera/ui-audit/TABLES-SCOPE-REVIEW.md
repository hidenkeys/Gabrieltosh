## Verified composition and safe boundaries

- `src/mera/workspace/OrganizationWorkspace.tsx`: Tables & visits navigation requires `tables.manage` (near line104). The main section near3126–3326 renders FloorMap, table cards/editors and creation, followed by visit cards/opening. A second tables conditional near3327 mounts Bills. The separate private-party access panel near1751 also serves reservations. Parent retains branch/actor authorization epochs, `mutate`, minimum-spend acknowledgment, private-code capture/rotation/reset, and financial journals.
- `FloorMap.tsx`: zone and table selection, saved-coordinate overlap warning, visual positions, keyboard arrows/Shift, sliders, explicit save/reset. Its existing `key={branchBase}` prevents draft reuse across branch remounts. Position edits change layout, not guests or visit tables.
- `TableEditor.tsx`: mounted native **Edit table & service status** disclosure containing separate table-metadata and service-status forms. `held` checks every open visit's `tableIds || [tableId]`; occupied/held tables cannot be returned to service through the form.
- `VisitTables.tsx`, `VisitMinimumSpend.tsx`, `PrivateVisitAccess.tsx`, `Bills.tsx`: reuse the existing leaves in place. Layout extraction must not remount them on every snapshot/version change or move secret code/state into a shared table card, map, journal or export.

Recommended presentation boundaries: (1) a small floor workspace wrapper for real map/list views and zone/status filters; (2) table inventory with selected-table editor and explicit creation disclosure; (3) current-party list/detail accepting authorized visit rows plus existing leaf slots/callbacks; (4) separate bill section, retaining its own financial controller. Root should continue owning creation/open/close handlers and private-party controls. Switching a visual view should preserve mounted drafts and pending intents. Missing table/visit collections must be unavailable rather than coerced to confirmed empty arrays.

## Concrete source gaps and acceptance

- FloorMap still exposes `table.id.slice(0,8)` in its ordinary selector. Table names are not currently guaranteed unique, so replace technical IDs with real zone/capacity/context and an explicit human disambiguation design; do not invent a new stable public identifier or uniqueness policy.
- “Current visits” maps the full supplied visits array, including closed records. Primary-table lookup can display raw tableId and omits combined table labels. Distinguish current parties/history and use canonical `tableName` or actual joined names with an honest unavailable fallback.
- The page repeats a map, full table-card inventory/editors, create form, all visit controls/open form and all bills. Group by staff task, with compact summaries and mounted disclosures, rather than duplicating selectors or forcing unrelated setup into live service.
- Open-visit select currently includes all tables; visibly unavailable/held choices should be explained or disabled using actual data, while backend remains final authority. New-visit feature gating must not disable existing paid service, code recovery or closure.
- FloorMap/TableEditor have no local in-flight/unknown fences or optimistic edit protection; delayed catches can outlive the selection. Preserve parent scope guards and document unsupported replay rather than adding local fake success. Dirty drafts should not be overwritten by polling; successful saves must not hide later staff changes indefinitely.
- Known source tests in `tests/mera-workspace.test.tsx` cover table permission, coordinate bounds, canonical move version/other-party exclusion, exact minimum acknowledgments, private code recovery and feature gates. These do not establish complete narrow-map keyboard use, unknown basic table edits/create/open/close, unavailable collections, long names/duplicate human labels, or full parent grouping.

Lead acceptance needs before/after desktop/tablet/narrow captures; explicit map/list selection and coordinate save/reset; keyboard/44px/focus checks; combined-party labels/held-state tests; closed-visit separation; real empty/unavailable/error states; and isolated request-race tests for unsupported versus versioned operations. Verify no raw guest/visit IDs or secret codes appear in normal cards/URLs/QR/export. No production data, provider, real payment or hardware action is authorized or claimed here.
