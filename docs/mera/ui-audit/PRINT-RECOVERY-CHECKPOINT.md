## Changes

Template saves and reprints now share one actor/branch-scoped unresolved-operation reference. It is stored before dispatch and contains only version, actor/base, operation, target ID (null for template save) and key. Template contents, reasons, customer documents and credentials are not persisted in this tab marker. Original request body stays in mounted memory. Storage errors block dispatch; no automatic resubmission on reads, mounting, reconnect or reload. This is tab-session recovery, not a claim that closing/deleting the tab preserves browser storage indefinitely.

Exact original retry, authoritative outcome check and transactional stop are explicit actions. Proof validates actor/org/branch/key/operation/target, recorded result and original metadata; template acknowledgment requires actual scalar ID/positive version in addition to the layout schema. A duplicate acknowledgment must identify a new marked queued job from the original source with physicalConfirmed false. Original normalized intent is compared when still held in memory. not_found, refreshed formats or refreshed queues never unlock another write. Only recorded or fenced abandoned proof clears the reference. After remount, no body is reconstructed: check or stop remains available. Both operations are blocked by a pending reference; parent mutation signatures cannot replace its key. Current actor expectation and scope guards remain enforced.

Dirty format drafts still survive saved-format reads. Recorded template recovery reads the latest saved format rather than treating the old original acknowledgment as indefinitely current. A stopped save keeps an available draft for explicit review. Permission loss clears private reprint reason, delayed error and original body while keeping only the reference; denied views clear private records and ignore late responses. A global notice and signout warning expose unresolved references. Shared connection errors now ask staff to check the original request outcome, without internal “canonical record” language.

Reprints use an explicit whitelist of existing document/order/batch/settlement fields. They retain the exact saved document snapshot but do not inherit prior browser-submission/completion fields or hypothetical claims. Fresh duplicate is queued, labeled/audited, automaticPaid false and physicalConfirmed false. No order recreation, money movement or readiness transition is introduced.
