## Authoritative recovery contract

Optional requestKey on existing POSTopen/close preserves legacy clients. Atomic branch-locked `shift_operation` stores the original acknowledgment and normalized intent, separate from current mutable shift state. Exact own-actor replay precedes lifecycle and cash calculation. Lookup verifies operation record, actor/scope/key/target and original intent; missing lookup does not prove failure or unlock another submission. Both operation records and stop resolutions have database append-only guards. Stop fences serialize with late writes; accepted operations are returned, never reversed.

The UI gets authoritative operation proof after a successful POST, not a fabricated envelope from current shift fields. Restore checks without automatically POSTing. Original acknowledgment is labelled as that operation, not a new count or current balance. Logout removes amount/reason before the parent callback and retains only the recovery reference/target; failed redaction blocks logout. Auth denial hides private details. Existing cash formulas, variance reason/review, manager approval, handover and financial-write journal semantics remain unchanged; no partial optimistic-version promise was added.
