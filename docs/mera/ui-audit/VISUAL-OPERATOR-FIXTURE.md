# Isolated visual operator fixture — review before use

This tool is prepared for review, not executed provisioning. It targets only the new visual QA cluster at127.0.0.1:55443 whose real SQL data_directory must equal this repository's data/mera-demo-visual-db. It never targets store3002, preview3003/55441, production or an arbitrary data path.

Default execution of `node scripts/mera-visual-operator.js` is a read-only preflight. It requires explicit nonproduction MERA_DEMO=true and DATABASE_URL for the local visual database. It checks the actual SQL server address/port and resolved data directory, then makes unauthenticated GET requests to127.0.0.1:3006 health and identity capabilities to verify local print simulation and demonstration registration. No password/factor is generated in dry run. Redirects and alternate targets are refused. No email is sent.

**Isolation limit:** HTTP health/capabilities corroborate that the visual endpoint is running in simulation. They do not cryptographically attest its database connection. The separate SQL data-directory check establishes exactly where provisioning writes can occur. The subsequent normal password/MFA flow will fail if that app uses another database or MFA key. Never describe the HTTP checks alone as app-to-database attestation.

Actual provisioning additionally requires the explicit `--provision` flag and a valid MERA_PLATFORM_MFA_KEY supplied through the operator's environment. The visual server must use that same32-byte key, encoded as64hex characters. The tool does not inspect running process environments, change existing keys, restart servers or create a preverified session. If the visual server lacks the matching key, its owner must start/restart **only the visual instance** with the key under a separate authorized operation.

Provisioning refuses an existing fixed fixture username or any existing platform factor; it never overwrites passwords/factors or promotes an existing merchant account. Under an advisory transaction lock it inserts exactly one new minimal local user with bcrypt password, one platform membership, and one encrypted TOTP factor. There are no merchant memberships, policy changes, provider credentials, sessions or MFA step-ups. The legacy enrollment CLI and live auth guards are untouched.

Generated credentials and the matching key are written exclusively into a newly allocated system temporary directory with0700 permissions, in a0600 file created withwx. Repository-local TMPDIR is rejected. Only the artifact path is printed, never credential values. Do not paste the file into chat, screenshots, logs or Git. The authorized reviewer must manage its short lifetime and remove it after QA; transaction failures remove the newly allocated artifact. A successful fixture deliberately remains available until explicit QA cleanup, without touching any other account.

Use the ordinary organization sign-in UI on the visual origin to submit its fixture username/password, then open /mera/platform and enter a current six-digit authenticator code. Session-bound MFA expires after10minutes; TOTP counters cannot be reused. Do not insert session/step-up rows or fake verified responses. Verify directory/filter/dialog/support/health/audit behavior at desktop/tablet/narrow sizes and record actual browser evidence. Mark all results synthetic local QA; they do not certify production operator enrollment, real merchant funds or provider operations.

Focused automated tests use mocked database/HTTP boundaries and temporary nonlive artifacts. They do not provision a real operator or connect to a running application/database.

For reviewed execution tooling, exported `loadVisualOperatorSecrets(path)` validates owner,0600 file/0700 directory, no symlinks, bounded size, system-temp location and fixture format, then returns credentials in memory. Never log that return value. `visualOperatorProcessEnvironment(path, baseEnv)` returns a new child environment with the same key and exact visual instance/ports; it refuses production and never modifies the parent environment. An authorized controller may pass it directly to `spawn(process.execPath, ['scripts/preview-mera.js'], {env, stdio:'inherit'})` after stopping only the visual instance. This helper does not launch anything itself. Do not use `cat`, shell command substitution or console serialization to transfer secret values. The ordinary browser login/MFA routes remain the only way to obtain an authenticated operator session.
